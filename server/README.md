Node only: the store, evidence, tools and transports. May use `class`. Never imports from `client/`; tested against a fake `PaseoApi`.

`server/evidence/` loads what a `show` displays, all within a 20-second budget: `confine.ts` reads one file (links resolved, confined to the workspace and permitted folders; the opened descriptor is checked through `/proc/self/fd` on Linux, and the non-Linux fallback narrows but does not close a parent-directory swap race), `git.ts` runs the three read-only git commands (`rev-parse`, `diff`, `ls-files`) with hooks, pagers, external diff and textconv off and `diff` run against a private git directory (so `.git/config`, `.git/info/attributes` and checked-in attributes can never name a filter that runs; no minimum git version beyond `rev-parse --show-object-format`, git 2.38+), `changes.ts` builds a `changes` block (ids `f1`, `f1h1`), `load.ts` loads every block and ref of a document, and `store.ts` writes snapshots (before the record) and compares hashes for "changed since". Pure parts live in `shared/evidence.ts`. Tests build fixture repos in temp dirs (`test-support.ts`).


Threat model: someone who can already write `.git/config` can add hooks or aliases that the user's own git runs, so evidence loading adds no exposure. Covered: no program from the repository's config, info/attributes or `.gitattributes` runs during loading, and no outside file is read through links on Linux. Not covered: `rev-parse` and `ls-files` still read the repository's config (their execution settings are overridden), and the non-Linux descriptor check is best effort.
